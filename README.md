# DOCX Format Validator

`DOCX Format Validator` — це простий Python-валідатор для автоматичної первинної перевірки оформлення студентських робіт у форматі `.docx`.

Інструмент не перевіряє зміст роботи, правильність технічних рішень чи якість викладу. Його призначення — швидко знайти типові порушення форматування: поля, абзаци, підписи до рисунків і таблиць, посилання на об’єкти, оформлення заголовків, список джерел тощо.

На вході валідатор отримує `.docx` файл, на виході формує текстовий звіт `report.txt` зі списком помилок, попереджень та інформаційних повідомлень.

## Структура файлів

Рекомендована структура репозиторію:

```text
.
├── docx_format_validator.py
├── docx_validator_config.yaml
├── requirements_docx_validator.txt
└── README.md
```

## Вимоги

Потрібно мати встановлений Python 3.10 або новіший.

Встановлення залежностей:

```bash
pip install -r requirements_docx_validator.txt
```

## Швидкий запуск

Базовий запуск:

```bash
python docx_format_validator.py Course_Petriv.docx
```

Запуск із конфігураційним файлом:

```bash
python docx_format_validator.py Course_Petriv.docx -c docx_validator_config.yaml
```

Запуск із явним шляхом до звіту:

```bash
python docx_format_validator.py Course_Petriv.docx -c docx_validator_config.yaml -o Course_Petriv.report.txt
```

Довідка по аргументах:

```bash
python docx_format_validator.py --help
```

## Формат звіту

Звіт має текстовий формат і групує повідомлення за рівнями:

```text
ERROR
WARNING
INFO
```

Приклад повідомлення:

```text
[ERROR] для рисунка 2.1 не знайдено згадки в тексті до його появи
    Місце: Розділ: РОЗДІЛ 2 ... > 2.1 Контейнеризація DVWA ...
           Об'єкт: підпис рисунка 2.1
           Пошук у Word: «Рис. 2.1 — Контейнери DVWA та MySQL у Docker Desktop»
           Технічно: абз. 86, елем. 91
```

Основний спосіб знайти проблему в документі — скопіювати фрагмент із поля `Пошук у Word` і використати `Ctrl+F` у Microsoft Word або LibreOffice Writer.

## Конфігурація

Основні правила винесені в `docx_validator_config.yaml`. Файл містить коментарі українською мовою, тому його можна редагувати під вимоги конкретної кафедри або дисципліни.

Наприклад, поля сторінки задаються так:

```yaml
page:
  margin_left_cm: 3.0
  margin_right_cm: 1.0
  margin_top_cm: 2.0
  margin_bottom_cm: 2.0
```

Щоб адаптувати валідатор під інші вимоги, достатньо змінити значення в YAML-файлі, не редагуючи Python-код.

## Що перевіряється

Валідатор перевіряє:

* параметри сторінки: формат, орієнтацію, поля;
* форматування основного тексту: шрифт, розмір, абзацний відступ, міжрядковий інтервал, вирівнювання;
* порожні абзаци підряд;
* нумерацію сторінок у верхньому або нижньому колонтитулі;
* заголовки розділів і підрозділів;
* зайву крапку після номера розділу або підрозділу;
* підписи до рисунків;
* підписи до таблиць;
* розміщення підпису рисунка після зображення;
* розміщення підпису таблиці перед таблицею;
* вирівнювання підписів рисунків і таблиць;
* наявність згадки рисунка в тексті до його появи;
* наявність згадки таблиці в тексті до її появи;
* дублювання номерів рисунків і таблиць;
* ситуації, коли підрозділ закінчується рисунком, таблицею або підписом;
* наявність списку використаних джерел;
* базові формальні ознаки оформлення джерел;
* посилання на джерела в тексті у форматі `[1]`, `[2–4]`, `[1; 3; 5]`.

## Нумерація сторінок

У конфігу можна задати вертикальне і горизонтальне розміщення номера сторінки:

```yaml
page_numbering:
  position: TOP
  alignment: RIGHT
```

Можливі значення `position`:

| Значення | Опис                                            |
| -------- | ----------------------------------------------- |
| `TOP`    | Номер сторінки має бути у верхньому колонтитулі |
| `BOTTOM` | Номер сторінки має бути у нижньому колонтитулі  |
| `ANY`    | Приймається номер або зверху, або знизу         |

Можливі значення `alignment`:

| Значення | Опис      |
| -------- | --------- |
| `LEFT`   | Ліворуч   |
| `CENTER` | По центру |
| `RIGHT`  | Праворуч  |

## Рівні серйозності

У секції `severities` можна змінювати рівень окремих правил:

```yaml
severities:
  caption_missing: ERROR
  paragraph_alignment: WARNING
  source_missing_year: WARNING
```

Доступні значення:

| Значення  | Опис                                       |
| --------- | ------------------------------------------ |
| `ERROR`   | Критична помилка оформлення                |
| `WARNING` | Попередження, яке варто переглянути вручну |
| `INFO`    | Інформаційне повідомлення                  |
| `OFF`     | Повністю вимкнути конкретне правило        |

## Що не перевіряється

Валідатор не перевіряє:

* зміст роботи;
* правильність технічних рішень;
* достовірність описаних результатів;
* академічну доброчесність або плагіат;
* читабельність рисунків на рівні зображення;
* фактичне розміщення об’єктів на сторінці після рендерингу;
* повну юридично точну відповідність списку джерел ДСТУ;
* кількість сторінок документа.

Для таких перевірок усе одно потрібен ручний перегляд викладачем.

## Рекомендований сценарій використання

1. Викладач запускає валідатор для студентського `.docx`.
2. Отримує `report.txt`.
3. Переглядає `ERROR`.
4. За потреби переглядає `WARNING`.
5. За фрагментом `Пошук у Word` швидко знаходить проблемне місце в документі.
6. Приймає фінальне рішення вручну.

## Приклад повного запуску

```bash
python docx_format_validator.py "Course_Petriv.docx" \
  -c docx_validator_config.yaml \
  -o "Course_Petriv.report.txt"
```

## Обмеження

DOCX-документи можуть мати складну внутрішню структуру. Те, що в Word виглядає однаково, всередині може бути оформлено по-різному: стилями, прямим форматуванням, Word-автонумерацією, таблицями без меж, розривами секцій тощо.

Через це валідатор варто використовувати як інструмент первинної перевірки, а не як абсолютний автоматичний вердикт.
